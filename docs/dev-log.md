# Dev Log

## 2026-09-15 — v4 «Воронка вероятности» + drill-down на v1-v3

**Задача:** добавить новую вкладку v4, показывающую задачи из отчёта Planfix 764900
(REST-генерация отчёта заблокирована тарифом, code 9001 — данные реконструируются из
аналитики dataTag 38590) как дерево месяц оплаты аванса → бакет вероятности заключения
(светофор) → задачи, с раскрытием и ссылками на задачи Planfix.

**Ключевые решения:**
- Отдельный кэш `FUNNEL_CACHE` + отдельные `/api/funnel` (GET) и `/api/funnel/sync` (POST),
  не пересекаются с `DATA_CACHE`/`/api/sync` — по требованию не задевать факт-логику.
- `fetch_probability_funnel()` возвращает плоский список записей аналитики (не агрегат):
  одна задача может дать несколько строк (разные материалы), группировка месяц→бакет
  делается на фронте.
- Фильтр как в отчёте 764900: объём>0, год оплаты аванса==2026, processId ∈
  {268814, 268846, 268960, 268958}. Неподписанные договоры и записи без вероятности —
  ВКЛЮЧЕНЫ (это дефолт отчёта, не баг).
- Заодно (в этом же диффе, реализовано и прошло ревью, но не было явно в исходной
  задаче) добавлен drill-down по кликабельным ячейкам факта на v1-v3: `/api/data` отдаёт
  новый ключ `planfix_details` с построчной детализацией, модалка на фронте показывает
  из чего сложилась сумма ячейки.

**Грабли:**
- У dataTag 38590 `customFieldData` приходит ПУСТЫМ, если явно не перечислить нужные ID
  полей в параметре `fields` запроса `/rest/datatag/38590/entry/list`.
- Поле 148320 (вероятность): если не заполнено — элемента с `field.id==148320` в
  `customFieldData` вообще нет (трактовать как `None`, не как 0/пустую строку).
- processId и другие поля уровня задачи (project/counterparty) в аналитику не входят —
  доборка отдельным `GET /rest/task/<id>` асинхронно с семафором (~25), по образцу
  существующего `get_tasks_signed_status`.
- Под `/dashboard/` все fetch к API обязаны быть относительными (`api/funnel`, не
  `/api/funnel`) — абсолютный путь даёт 404.
